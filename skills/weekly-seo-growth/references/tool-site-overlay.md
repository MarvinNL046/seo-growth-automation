# Tool-site overlay

Apply this overlay to image compressors, generators, word tools, wheels, QR tools, and calculators. It supplements the 99-item snapshot; it does not silently rewrite it.

## Schema

- Use `WebApplication` or `SoftwareApplication` for a genuine interactive tool.
- Include only truthful fields such as name, URL, application category, browser operating-system support, and a zero-price offer when the complete tool is actually free.
- Use `FAQPage` only for questions and answers visible on the page. Do not promise rich-result eligibility.
- Use `BreadcrumbList` on non-home routes and `WebSite`/`Organization` site-wide where accurate.
- Never add fabricated ratings, review counts, authors, awards, prices, or organisations.

## Product and UX evidence

- Keep the primary tool and its useful controls above the fold where practical.
- Verify the complete task: input, validation/error state, result, copy/download/reset, keyboard flow, and mobile flow.
- State privacy, security, browser-only processing, limits, supported formats, randomness, or calculation assumptions only when verified in code.
- Explain methodology for calculated outputs and link to authoritative definitions where relevant.
- Prefer a material tool improvement over a thin keyword variant.

## Landing-page guard

Create a format/use-case page only when its SERP intent, tool configuration, copy, examples, FAQ, internal links, and value differ materially from existing routes. A swapped H1 and keyword is a doorway page and must not ship.

## Tool conversion branch

For a free tool with no lead-gen or affiliate model, mark both canonical conversion branches N/A with reasons and validate instead:

- a clear above-fold primary action;
- immediate feedback and recovery from errors;
- a useful next action after result generation;
- no deceptive urgency or unsupported trust claims.
